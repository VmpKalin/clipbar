# ClipBar — clipboard manager (v1) design

Date: 2026-10-25

## Goal

A Maccy-style clipboard history manager, built with SwiftUI and Liquid Glass,
running on iOS 26+ and macOS 26+ from a single codebase. The user copies as
usual; the app keeps everything (text, links, images), lets them pin, save,
search and re-copy any item, and on macOS opens path-like items in Finder or
Terminal. The app is the first "tool" of a future multi-tool app.

## Platform constraints and how they shape the design

- **iOS** cannot observe the pasteboard in the background. The app reads
  `UIPasteboard.general` every time it becomes active. A Control Center
  control and a Home/Lock Screen widget open the app in one gesture so the
  "copy → tap → saved" loop takes a second. Before reading, the app compares
  `changeCount` with the last seen value so unchanged pasteboards are never
  read (and the system "Allow paste?" banner does not appear needlessly).
  Onboarding explains Settings → ClipBar → Paste from Other Apps → Allow.
- **macOS** can poll `NSPasteboard.general` (`changeCount` every 0.5 s), so on
  Mac the history fills automatically, like Maccy. macOS also has Finder and
  Terminal, so "Open in Finder" / "Open in Terminal" exist there. On iOS a
  file path item offers "Open in Files" via the `shareddocuments://` scheme
  when the path is inside a Files-visible location; otherwise the action is
  hidden.

## Architecture

Single Xcode project generated by XcodeGen (`project.yml`), targets:

| Target | Platforms | Purpose |
| --- | --- | --- |
| `ClipBar` | iOS, macOS | The app |
| `ClipBarWidget` | iOS | Home/Lock Screen widget + Control Center control (both just open the app) |
| `ClipBarCore` | iOS, macOS (framework-less: a folder of shared sources compiled into both app and tests) | Model, store, capture logic, path detection |
| `ClipBarTests` | macOS (host-less unit tests) | Unit tests for core logic |

No third-party dependencies.

### Data

SwiftData model `ClipItem` stored in the App Group container
(`group.com.aholoiad.clipbar`) so the widget and a future keyboard can read it.

```
ClipItem
  id: UUID
  kind: ClipKind (text | link | image | filePath)
  text: String?            // text, URL string, or path
  imageFileName: String?   // file in <AppGroup>/Images/, PNG
  thumbnailData: Data?     // small JPEG for list rows
  contentHash: String      // SHA-256 of text or image bytes, dedup key
  createdAt: Date
  lastUsedAt: Date
  useCount: Int
  isPinned: Bool
  isSaved: Bool
```

`ClipKind` is derived at capture time by `ClipClassifier`:
- image bytes present → `image`
- text parses as a URL with scheme http/https → `link`
- text starts with `/`, `~/`, or `file://`, and is a single line → `filePath`
- otherwise → `text`

### Core components (all in `ClipBarCore`, platform-neutral where possible)

- `ClipStore` — the only writer to SwiftData. API: `ingest(_ payload: ClipPayload)`,
  `markUsed(_:)`, `togglePin`, `toggleSaved`, `delete`, `clearHistory(keepPinnedAndSaved: Bool)`,
  `enforceLimit(_ limit: Int)`. Ingest dedups by `contentHash`: an existing
  item is moved to the top (`createdAt = now`) instead of being duplicated.
  `enforceLimit` deletes the oldest unpinned, unsaved items beyond the limit.
- `ClipPayload` — plain struct (`text` or `imageData`) that the platform
  pasteboard readers produce. Classification and hashing happen here.
- `PasteboardReader` (protocol) with `UIPasteboardReader` and `NSPasteboardReader`.
  Each remembers the last `changeCount` and returns `nil` when unchanged.
- `PasteboardWriter` (protocol) with platform implementations.
- `CaptureCoordinator` — iOS: triggered on `scenePhase == .active`; macOS:
  a 0.5 s timer. Calls reader → store.ingest. Skips writes the app itself
  just made (it records the `changeCount` after writing).
- `ImageFileStore` — writes PNG + makes a 160 px JPEG thumbnail, deletes files
  when an item is deleted.
- `PathActions` — `resolve(path) -> URL?` (expands `~`, strips `file://`,
  checks existence). macOS: `openInFinder(url)` selects the file or opens the
  folder; `openInTerminal(url)` runs `open -a Terminal <dir>` where `<dir>`
  is the path itself when it is a directory, otherwise its parent.
  iOS: `filesAppURL(for:)` builds `shareddocuments://` URL.

### UI (SwiftUI, Liquid Glass)

- `RootView`: `NavigationSplitView` on macOS/iPad; on iPhone a custom
  left drawer (`SideMenuView`) that slides in from the left on a menu button
  or an edge swipe, over a dimmed main view, using `.glassEffect`.
- `SideMenuView`: sections with counts — All, Pinned, Saved, Frequent, Images,
  Links, Paths — and Settings at the bottom.
- `HistoryListView`: searchable list for the selected section. Rows:
  - text: up to 2 lines, monospaced if it looks like code/a command.
  - link: domain bold + full URL secondary.
  - path: last path component bold + full path secondary, folder/file icon.
  - image: thumbnail, dimensions caption.
  Pinned items always sort first in All. Frequent sorts by `useCount` desc then
  `lastUsedAt`. Images section is a 3-column grid.
- Interactions: tap = copy to pasteboard + haptic (iOS) + `markUsed`.
  Swipe leading = pin/unpin, trailing = delete. Context menu: Copy, Pin,
  Save, Share, Open in Finder / Open in Terminal (macOS, path items only),
  Open in Files (iOS, path items), Delete. On macOS the list also supports
  ⌘1…⌘9 to copy the first nine visible items, like Maccy.
- `SettingsView`: history limit (100/500/1000/unlimited; default 500),
  clear history (keeps pinned and saved), "Allow paste" hint (iOS), launch at
  login hint (macOS, informational only in v1).
- Toolbar uses Liquid Glass (`.toolbar` + `.glassEffect`, `GlassEffectContainer`).

### Widget and Control Center (iOS)

`ClipBarWidget` target with:
- `RecentClipsWidget` — small/medium widget showing the 3 most recent items
  (reads the shared SwiftData store); tapping opens the app via `clipbar://`.
- `OpenClipBarControl` — `ControlWidget` button that opens the app
  (`OpenIntent` conforming to `AppIntent` with `openAppWhenRun = true`).

### Error handling

- Pasteboard read failures or unsupported content → ignored silently.
- Image write failure → item not stored, logged with `os.Logger`.
- Path actions on a non-existent path → action disabled in the menu.
- SwiftData container failure at launch → fall back to an in-memory container
  and show a banner "History won't be saved".

### Testing

Unit tests (`ClipBarTests`, macOS host, in-memory SwiftData):
- `ClipClassifier`: text / link / path / image detection, `~` expansion rules.
- `ClipStore`: ingest dedups and bumps to top; `enforceLimit` keeps pinned and
  saved; `markUsed` increments and sorts Frequent correctly; `clearHistory`
  keeps pinned/saved.
- `PathActions.resolve`: expands `~`, strips `file://`, rejects missing paths,
  picks parent dir for files when computing the Terminal directory.

Manual/simulator verification: build for iPhone 17 Pro simulator, launch,
seed pasteboard via `xcrun simctl pbcopy`, foreground the app, verify list,
screenshot. Build for macOS and run unit tests via `xcodebuild test`.

## Out of scope for v1

Keyboard extension, Share Extension, iCloud sync, tags/folders, editing item
text, menu-bar popover on macOS (the Mac app is a normal window in v1).
